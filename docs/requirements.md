# ヘアアポ(仮) 要件定義 v0.3

## 確定事項

| 項目 | 決定 |
|---|---|
| サービス名 | ヘアアポ(仮称、後で正式決定) |
| 初期ターゲット | スタッフ数で絞る。推奨: **1〜10名**(個人〜小規模)。1人営業は「スタッフ=オーナー」の簡易モード |
| 立ち上げ | SaaS先行(予約・顧客管理)、集客モールは後 |
| 予約方式 | 空き枠即時確定 |
| 料金案 | **月額1万円 + 予約経由売上の8%(決済手数料込)** |
| 現地払い | 両方対応(事前決済は売上相殺、現地払い分は月末締め請求)。どちらが増えるか見て主軸を後で決める |
| 決済形態 | 全部あり: 事前決済 / 現地払い+カード登録 / 現地払いのみ → **サロンがメニュー・客層別に選択** |
| 技術 | 完全新規コードベース。Next.js + TypeScript + Supabase + Stripe Connect(型あり) |
| 初期サロン | THEATER(調査のみ、直接ヒアリングはまだしない) |

## 1. 料金モデルの妥当性チェック

### 競合対比(月額+変動費)
| サービス | 月額 | 変動費 | 送客 |
|---|---|---|---|
| **ヘアアポ(案)** | ¥10,000 | 8%(決済込) | 独自URL中心、モールは後 |
| STORES予約 スモール | ¥9,790(年契約) | 決済3.3%〜(別) | なし |
| STORES予約 チーム | ¥19,690 | 同上 | なし |
| STORES予約 フリー | ¥0 | 決済5.2%〜 | なし |
| HOT PEPPER Beauty | 掲載料(数万〜数十万) | 送客手数料+ポイント原資 | あり |

- 8%込み → カード実費〜3.6%を引くと実収は約4.4%+月額1万
- STORES予約より月額は同水準だが変動が高い → **「送客なし予約台帳」だけでは8%が払いにくい。8%を正当化するには新規送客 or リピート管理価値が要る**
- 代替案(要検討): 手数料を「自前導線(店舗URL・SNS)は決済費相当の〜4%」「モール経由送客は8%」の2本建てにすると説得力が上がる。モール未ローンチ期間は実質4%運用でも成立
- HPB対比の売り文句: 掲載料なし・リピート条件をサロン側が選べる・手数料明細を透明表示

### 1人〜10名を推奨する理由
- 1人営業: 予約は最も単純(指名なし・シフト=営業時間)。ただし支払い力は低い
- 2〜10名: スタッフ指名・シフト管理が本当の価値になる最大の市場。HPB手数料負担感も強い
- 10名超・複数店舗: 権限/店舗間/統合レポートが必要になりMVPが膨らむ → P2以降

## 2. MVP機能要件

### 2.1 サロン側(管理画面)
- **予約台帳**: 日/週カレンダー、スタッフ別、手入力予約(電話・HPB併用期間用)
- **空き枠公開**: 営業時間・シフト・ブロック − 既存予約 = 公開枠。即時確定は台帳の正確さが生命線
- **メニュー管理**: 価格・所要時間・前後バッファ、スタッフ別対応可否・指名可否
- **シフト**: スタッフ別出勤/休み(繰り返し)、休憩ブロック
- **顧客・カルテ**: 来店履歴・施術メモ・写真・注意事項
- **決済設定**: メニュー/客層別に「事前決済/カード登録のみ/現地払い」を選択
- **請求**: 手数料明細の透明表示(対HPB差別化)
- 店舗独自予約URL(Instagramプロフィール等から直リンク)
- **通知**: LINE/メール(予約確定・変更・前日リマインド)

### 2.2 客側
- 店舗ページ(メニュー・スタッフ・空き枠)
- 予約フロー: メニュー → 指名/フリー → 空き枠 → 情報入力 → 支払方法に応じてカード決済/登録 → 即時確定
- 予約確認・変更・キャンセル(LINE/メールのリンクから)
- 会員: LINEログイン or メール、ゲスト予約は要検討

### 2.3 運営側
- 店舗アカウント・KYC進捗、請求管理(現地払い分の売掛)、ノーショーフラグ

### 2.4 スコープ外(MVP)
- POS/会計、DM一斉配信、モール検索、ポイント、ネイティブアプリ、複数店舗

## 3. データモデル骨格

- `salon`, `staff`, `menu`(価格・時間・バッファ・支払方式), `staff_menu`
- `shift`(staff×曜日/日付), `time_off`
- `customer`, `kart`(履歴・写真・メモ)
- `appointment`(status: confirmed/cancelled/no_show、payment_mode)
- `payment`(stripe_pi、手数料・入金額), `invoice`(現地払い分手数料・月次請求)
- 競合制御: staff×時間枠ユニーク制約 + トランザクション(ダブルブッキング防止)
